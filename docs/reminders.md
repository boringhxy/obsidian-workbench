# 接入 Apple 提醒事项

## 前置条件

macOS、已有Obsidian知识库、已安装[Remindian](https://github.com/Santofer/Remindian)。参考部署验证版本为Remindian 5.34.1；其他版本请先使用测试清单核对。工作台本身不会读取或保存GitHub令牌、Apple账号或Remindian其他服务的API凭据。

先在苹果提醒事项新建“工作台”清单，在Remindian的Browse中选择自己的真实知识库，完成提醒事项与文件访问授权。

## 正式配置

| 设置 | 建议值 |
| --- | --- |
| Task Source | Obsidian Tasks |
| Sync To | Apple Reminders |
| Default list | 工作台 |
| Only scan | 工具/个人工作台 |
| Only sync lists | 工作台 |
| Unmapped tags create lists | 关闭 |
| Global filter、Only notes tagged | 留空 |
| Sync state storage | Application Support，本机存储 |
| 其他正式／测试配置 | 先停用，避免重复处理同一任务 |

先用Dry run检查范围，确认不会计划删除旧提醒。正式安装的`--enable-reminders`要求Dry run已关闭，并要求只启用选中的配置。

安装器启用文件监听、启动同步、1分钟定时同步、具体时间、提醒闹钟，以及完成、到期日期和优先级回写；仅设日期的默认提醒时间为09:00。关闭内部标签备注。它不会启用“提醒事项中新建任务导入”，不会修改开机自启动系统注册，也不会替代系统授权。

Remindian需要保持运行。保存到Obsidian与已经送达提醒事项是两个阶段；首次请点击主窗口右上角Sync Now，核对标题、日期、具体时间、优先级，再在提醒事项完成一次并确认Markdown已更新。

## 验证边界

- 已在参考部署核对：任务创建、简洁标题更新、完成状态回写。
- 已通过代码测试：具体时间、午夜、优先级、备注、编辑清空、元数据迁移与原提醒ID保留。
- 尚需按环境实测：任意具体时间的完整送达、系统通知准点响起、日期与优先级修改后的回写。
- 工作台备注只承诺保存到工作台，标题与备注的任意双向编辑没有完整保证。
- 仅设日期的提醒也会按工具配置获得默认闹钟；启用闹钟不一定追溯修改所有已有提醒的闹钟。
- `📅 YYYY-MM-DD HH:mm`并非Tasks通用时间标准，其他编辑器可能去掉时间。
- 通知效果还受系统提醒事项通知权限、专注模式和应用运行状态影响。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 输入后没有提醒 | 确认在Obsidian正式视图输入；HTML只是演示。检查真实源文件、最新同步日志与应用是否运行 |
| “今天”列表看不到 | 到“工作台”清单查找；无日期或非当天的任务不会进入“今天” |
| 找不到Sync Now | 在Remindian主窗口右上角，不是单独的设置窗口 |
| 标题出现yu编号 | 使用1.4.1；旧任务需在退出两个应用后执行启用提醒事项的迁移安装，再同步 |
| 备注出现Tags编码 | 关闭writeTagsToReminderNotes，重新同步并核对原生备注栏 |
| 大量删除被保护拦截 | 检查知识库、扫描文件夹和过滤器，不要提高限额或重置全部状态 |
| 安装器拒绝历史关联 | 索引可能含其他笔记的任务，先备份和核对；此通用安装器不会自动解除陌生关联 |
| 只有日期没有具体时间 | 在任务详情开启时间，同时开启Include due time和Add reminder alarm |
| 编码清理后重名 | 同名同标签任务可能冲突；迁移器停止，保留源文件和原提醒，需先人工判断 |

历史参考部署曾有55条索引，收窄范围后仅8条属于工作台，工具计划删除47条并触发保护。处理方式是备份后解除范围外关联，保留原提醒；不是提高删除限额。本仓库只保留设计说明，不分发任何真实索引或针对个人部署的修复脚本。
